# Adjacent Franken-suite opportunities for FSS

**Document class:** prospective import census
**Status:** candidates; not admitted merely by mention

The user-requested deep dives define the core substrate. Several adjacent first-party projects can further reduce external dependencies. Each remains behind the same mechanism/invariant/reference/failure/admission contract; FSS does not import a crate because its name begins with “Franken.”

## `frankentui`

Potential imports:

- diff-based terminal rendering;
- RAII terminal restoration;
- inline/non-alternate-screen modes;
- bounded input/event processing;
- deterministic widget snapshots;
- operations-console components.

FSS use: `fss ops`, device-lab dashboards, transfer/repair visualization, timeline inspection, qualification status. The TUI consumes bounded public projections and cannot hold secret or effect authority merely because it is local.

## `frankenui`

Potential imports:

- pure-Rust desktop UI shell;
- retained scene graph and diff rendering;
- Vello-style accelerated vector composition;
- typed state/update model;
- no Electron, browser engine, Node runtime, or Tauri dependency.

FSS use: multi-camera live wall, incident timeline, calibrated 3D site view, privacy-mask editor, device enrollment, evidence export review. Media surfaces remain generation-pinned and privacy-scoped.

## `frankentorch`

Promoted to a full deep dive because pure-Rust production inference is constitutional. See [`FRANKENTORCH.md`](FRANKENTORCH.md).

## `franken_whisper`

Potential imports:

- pure-Rust speech/audio inference;
- chunked streaming and timestamp evidence;
- diarization/acoustic-event contracts;
- model package and performance ledgers.

FSS use: optional local speech transcription, glass-break/alarm/dog/bang cues, audio-video temporal corroboration. Audio remains opt-in and privacy-restricted.

## `franken_ocr`

Potential imports:

- pure-Rust OCR pipeline;
- geometric text spans;
- confidence and preprocessing receipts;
- deterministic document/image outputs.

FSS use: package/vehicle markings or signage in user-authorized evidence investigations. OCR text is tainted derived evidence, never identity truth.

## `frankenmermaid` and `franken_markdown`

Potential imports:

- deterministic architecture/incident diagrams;
- same-source HTML/PDF reports;
- no browser/JavaScript rendering dependency.

FSS use: doctor bundles, evidence reports, calibration diagrams, graph explanations, release proof books.

## `franken_networkx` Forge/code generation

Potential import beyond runtime algorithms: generate shape-specialized graph kernels for frozen FSS projections, while retaining the generic reference oracle. Examples include fixed camera-transition graphs, zone-cut analysis, bipartite association, and bounded coverage set systems.

## `frankensim` family

Potential imports:

- deterministic physical/sensor simulation;
- typed refusal when validity envelopes are exceeded;
- multi-fidelity reference/optimized solvers;
- browser/WASM visualization only as a derived presentation.

FSS use: synthetic calibration, occlusion/coverage fixtures, camera placement counterfactuals, drone-capture planning, and adversarial scenario generation. Simulation never substitutes for observed deployment evidence.

## Admission rule

For every adjacent project, FSS requires:

1. exact mechanism and semantic owner;
2. dependency-direction review;
3. no second runtime or ambient authority;
4. deterministic reference behavior;
5. qualification on FSS workloads;
6. graceful failure or reference fallback;
7. no aggregate readiness inference from the sibling repository;
8. exact revision capture in DSR release receipts.
