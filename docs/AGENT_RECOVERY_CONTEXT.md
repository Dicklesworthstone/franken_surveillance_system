# Durable context for agent recovery

## Historical harmful outcomes

Operational memory now enters the canonical situation before context selection, fingerprinting,
compression and handoff sealing. Repeated negative feedback or failed episodes can produce a
trauma-guard warning for an exact target and attribution cause. The warning carries its retained
record identities, evidence roots, count and deterministic decay weight.

Use the principal that owns the operational history:

```bash
fss orient --json --root "$DEPLOYMENT_ROOT" --principal "$PRINCIPAL" --view brief
```

The same projection is used by durable session opening, handoff and resume, including the
orientations returned by session-scoped investigation, feedback and planning operations. A new
harmful-history warning changes the sealed situation fingerprint even when the authority ledger
has not advanced. Resuming a previous handoff therefore detects changed agent context and advances
the workspace instead of silently reusing its old situation.

### Visibility and meaning

The loader includes only records owned by the requested principal. Historical sessions or missions
of that principal may contribute; records from another principal do not contribute targets,
counts, warning identities or citations. Durable-session loading requires situation-read and
`private:property` visibility. The standalone CLI principal is still an audit label under the
operator's filesystem authority; this change does not create an authentication mechanism.

A known memory proposition establishes that the retained reports exist. It does not establish
that the target is harmful now, that a previous failure applies to the current mission, or that a
policy change is justified. Applicability remains an explicit unknown. Derivation never changes
thresholds, policy, retention, models, capabilities, authority-ledger history or effect records.

Warnings are protected risk context. Selection must retain them within the admitted view budget
or return the existing context-budget refusal. It cannot return a smaller successful answer that
silently dropped the warning. A caller that did not load or could not admit operational memory
gets an explicit unavailable projection, which is different from a successful scan with no
recurring warnings.

### Recovery and failure boundaries

Publication roots, canonical records and required children are verified. Failed episodes must
bind their exact retained plan, owner, session, mission and operation. Missing or corrupt history
is refused; the loader does not rename an unresolved event target to a plan target or turn a
failed read into an empty warning list. A missing publication directory is the supported empty
case. A present malformed or unreadable directory is not.

The loader bounds source records, materialized bytes, warning count, citations and summary size.
Its 16 MiB materialization limit is additional to the publication inspector's structural bounds;
it is not a measurement of all filesystem reads or metadata operations. The deployment snapshot's
reported read cost does not meter these additional publication-inspection reads.

Adjacent history replay refuses supplied current advisory warnings because it has no retained
session-history witness for applying them to historical endpoints. A fresh orientation or handoff
resume reconstructs current authorized memory instead of claiming a historical replay of it.

### Repeating an opening request

An exact retry authenticates the live session and reuses its immutable revision-zero workspace,
while returning the current authorized orientation. It does not reopen the session, refill its
budget, renew its lease, restore removed grants, or replace the original context. Closed or expired
sessions remain unavailable. Changed authority anchors or contract bases require the existing
resume/rebase path.

A session interrupted before its first workspace can complete only through the original
request-digest check, with its exact retained mission and original grants still present. Nonempty
workspace history without its opening revision, or a missing or corrupt mission, is refused.
