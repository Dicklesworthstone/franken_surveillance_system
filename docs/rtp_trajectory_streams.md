# Native-replayable RTP trajectory transcripts

The `ingest::rtpdump::track_stream` reference API exports anonymous within-camera
trajectories from a completed retained RTP import and an independently verified neural
package. `write_tracking_stream` owns the actual source → checked native H.264 decode →
RGB inference → complete detector-head projection → existing tracker path. It does not
accept caller-assembled boxes, tracks, pixels or claimed decoder receipts.

`verify_tracking_stream` repeats that complete native path with the caller's explicit
request and compares every generated byte to the saved stream. It also requires an
independently supplied SHA-256 and final saved EOF. Saved lengths are never parsed for
allocation; a saved recipe cannot change the model, mask, class or execution budget.
Rehashing a modified transcript does not make it agree with the original native results.

## Preserved evidence and bounds

The transcript carries source record positions and refusal classes, decoder admission,
retired-group and IDR-recovery consequences, every complete native frame receipt with
its original source spans, detection and inference identities, all detector row
exclusions, all pre-NMS candidates and suppressor links, all retained source-space
proposals, and actual tracker observations with their predecessor and reset epochs.
Boxes use native outward-rounded 1/256-pixel bounds; scores retain their exact F32 bits.
Coasting predictions are counted as active tracks but never serialized as observations.

The original neural tensors are referenced by their existing complete inference digest,
not copied into the transcript. The source error class is serialized, not internal Rust
Debug text or the full nested codec error. Exact source bytes, selected native recipe
and record placement permit native re-investigation. These omissions are declared in
the header rather than presented as a complete model-tensor archive.

Independent stream-byte, record-count and conservative frame-encoding allocation
ceilings supplement the unchanged native, custody, inference and association budgets.
Every complete record is admitted before its first I/O; partial writes consume bytes.
Reads and writes are at most 4 KiB, with at most eight interrupted calls at an offset.
Both caller cancellation contexts are checked throughout encoding, I/O and delivery.
I/O refusal stops further native work. Flush failure returns no successful summary.
File creation, path authorization, synchronization and independent digest retention
belong to the caller.

## Completeness is not absence

The default `CompleteSource` policy refuses a terminal transcript when native source,
inference or tracking is incomplete. `SourceDiagnostics` is a separately bound opt-in:
a fully enumerated source-refusal history can retain successful tracked frames, but
`summary.stats.complete()` remains false. It never admits a failed numerical stage,
exhausted tracking allowance or cancellation. Zero-frame histories receive no successful
trajectory summary, under either policy. The source-progress prefix may be kept as
incomplete diagnostic bytes, not certified as a finished transcript.

Motion units are observed-frame steps, not seconds. Sender RTP timestamps do not narrow
the original conservative capture interval. The stream grants no physical identity,
calibrated threat, absence, live camera coverage or effect authority. Native frame and
tracker identities are unchanged by this serialization layer.

## Format v1

Each record is framed by the existing canonical encoder's `u64(sequence)` and
`u64(payload_length)`. Sequence begins at zero and includes header and terminal.
The first payload byte identifies header (0), source progress (1), tracked frame (2),
or terminal accounting (3). Integer and length semantics are the existing FSS canonical
encoding, not Rust memory layout or Serde derivation. The header binds domain
`fss.retained_rtp_tracking_stream.v1`, version 1, original root, verified package,
tracking recipe, interpretation/omission declarations, and independent admissions.
The terminal binds the last frame, native recipe, pre-terminal byte/record counts and
all original stage counters. The independent stream hash covers every byte including
that terminal. A hash match alone is not a successful native verification.

## Scope and validation

This is a reference slice of Beads `fss-2h5zq.77`: canonical trajectory export and
original-source replay. It is not yet a deployment-owned root-last trajectory object
graph, a cold metadata-only graph reader, or a new hold/deletion dependency registration.
Deleting the original source prevents future native verification; previously exported
files remain separately controlled copies and are not implicitly deleted.

The tests use actual retained H.264, the checked-in YOLOX-Nano package, fresh recovery
inspection, changed privacy, missing source bytes, source gaps, corrupt saved streams,
short I/O, cancellation and exhausted bounds. Run `bash scripts/check_rtp_tracking.sh`
with the pinned toolchain and provisioned locked dependencies. Source presence is not a
native test-pass, camera qualification or release claim.
