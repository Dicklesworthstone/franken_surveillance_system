# Changelog

All notable changes to Franken Surveillance System are recorded here. The project is pre-release; entries describe implemented and retained repository state, not production qualification unless explicitly stated.

## Unreleased

### Added

- Added sensor- and event-scoped deletion closure (`fss-x4a.30.86.20`, `fss-x4a.30.86.21`; `CAP-DELETE-PREPARE-001` subject/object/event scope). `fss-event delete plan --sensor-id ID | --event-id ID` (mutually exclusive with `--import-id`; exactly one required) seals one plan over the union closure of every retained import of the sensor (by its capsules) or of the event (imports whose closure reaches its revisions), members sorted; shared objects held outside the scope stay retained and listed. The scope kind and id are bound into new `fss.deletion_plan.v2` / `fss.deletion_completion.v2` bytes (import plans keep their exact v1 bytes), so a scoped plan cannot be replayed as an import plan and a tampered scope has no current plan. `delete commit` reuses the same revalidation, approval, tombstone-first record and exactly-once resume; an owner evidence hold on any member import blocks the whole plan. New refusal `ERR-DELETION-SCOPE-EMPTY-001`. Local filesystem unlinking only: not cryptographic erasure, no replicas or archives. There is no person/data-subject identity in the system, so no subject scope exists beyond a sensor.
- Added raw-export privacy refusal (`fss-nswce`): `fss-archive export` now requires `--privacy-root DIR --site SITE` naming the deployment retaining the sensor's privacy-mask authority and refuses a masked sensor, or an export naming no deployment, before any output (`ERR-PRIVACY-UNMASKED-ACCESS-REFUSED-001`, no override). Unmasked exports are byte-identical. The deletion-hold half of `fss-nswce` was superseded by the owner's evidence holds (`fss-hold`) and not landed.
- Added the first registered graph algorithm family end to end (`fss-w96u7`, FSS-165 `fss-x4a.23.15`): `ALG-BRIDGE-001` articulation points and bridges in the new `fss-graph-algorithms` crate (iterative Tarjan DFS with low links over a canonical immutable undirected simple graph; strict input, registered stable-identity tie-break), with root separations (the exact nodes each cut vertex or bridge disconnects from a root). Every run emits `GraphAlgorithmWitness` v1 (fss-core, `fss.graph_algorithm_witness.v1`: algorithm/implementation/projection identity, anchor, n/m, projection digest, policy, dominant operation counts, accounted working bytes, budget, exactness, stop reason, decision-path and output digests) and checks the counters against the registered bound at run time; budget exhaustion and bound violation fail closed (`ERR-GRAPH-BUDGET-EXHAUSTED-001`, `ERR-GRAPH-COMPLEXITY-BOUND-001`; also `ERR-GRAPH-INPUT-INVALID-001`, `ERR-GRAPH-RESULT-INCONSISTENT-001`). Certified against a brute-force removal oracle on 4,000 seeded graphs and by insertion-order, orientation and relabelling metamorphic tests. `fss-event graph single-points --root DIR --site SITE` answers, read-only, which single sensor loss leaves each zone without any retained coverage witness (`SensorCoverageGraph` over retained coverage records; report `fss.coverage_single_points.v1`). Five digest domains registered (114). The registry row is `implemented`, not qualified: no FrankenNetworkX differential, snapshot-invalidation, noninterference or incremental lanes exist.
- Added privacy masks on live, recording and replay decode paths (`fss-g9gml`): live HTTP acquisition (learned HOG via a new `fss-twin` decoded-plane redaction hook, and RGB neural), archived HTTP RGB replay, HTTP recording decode, `fss-archive check-http` (new `--privacy-root DIR --site SITE --sensor ID`, required for decoding checks) and RGB evidence replay apply the named sensor's current retained policy (`privacy_mask::live::SensorMask`) with the fss-bgqkd enforcement and fills, per decoded frame; a masked frame's luma digest equals the retained decode's. Owner permission grids or frozen backgrounds admitting masked pixels, decodes naming no sensor and RGB evidence recorded under a non-current binding are refused (`ERR-PRIVACY-UNMASKED-ACCESS-REFUSED-001`). Completions and receipts name the applied policy; no-policy bytes are unchanged (golden-pinned against the pre-change code); masked RGB evidence uses recipe `fss.rgb_source_evidence.recipe.v2` (digest domains 109 -> 110). Also masks retained MJPEG sensor-health screening, which digested unmasked luma. RTSP live capture decodes no pixels (source-scan test).
- Added graph-complete deletion closure of retained imports (`fss-x4a.9.7`, FSS-037; `CAP-DELETE-PREPARE-001`, `CAP-DELETE-COMMIT-001`, `PUB-DELETE-001`). `fss-event delete plan --import-id sha256:…` is read-only: it scans every retained object once for embedded digests, walks every ledger batch and visible root that holds, names or embeds a digest of the import's derivatives (custody, decoded frames and receipts, coverage and package-detection records, event provenance, attributable staging leftovers) and prints a sealed plan (`fss.deletion_plan.v1`): units and the reference that reached each, objects and bytes removed, objects retained (shared with retained authority, or authority history), the tombstone batch, blockers and unknown copies (the input file, unrecorded operator exports, transmitted alerts). `delete commit --plan … --approve …` refuses a stale plan (`ERR-DELETION-PLAN-STALE-001`) or a blocked one (`ERR-DELETION-BLOCKED-001`, e.g. an indeterminate alert on the evidence) before any write, then appends the deletion record first (reserved families `deletion_record`, `deletion_tombstone`, `local_root_retraction`; `KNOWN_LEDGER_DELTA_FAMILIES` is now 15), unlinks root records and spool objects (hold first), verifies absence and appends the completion record (`fss.deletion_completion.v1`); a rerun after an interruption at any cut point completes exactly once with identical bytes. Reads, decodes, re-imports and plans of a deleted import report `ERR-EVIDENCE-DELETED-001`; events keep every revision and orient/explain name their evidence as `deleted`. Root/ledger reconciliation treats a retracted claim as history. Local filesystem unlinking only, never cryptographic erasure; no hold registry, retention schedules or remote/replica deletion.
- Added deterministic multi-threaded Conv2d to the optimized executor (`fss-zczw0`). Callers pass an explicit `ExecThreads` count (1..=64; 0 and larger counts are refused with a typed `ExecThreadsError`) to `OptimizedGraph::run_threaded`, `RgbInferenceModel`/`RgbDetectorPackage::with_execution_threads` or `fss-infer package-detect --threads N|auto` (default 1). Output units are split into contiguous `split_at_mut` chunks that `std::thread::scope` workers take from a bounded local queue. Every element is written by one thread using the unchanged operation order, so outputs, digests, identities, receipts and report bytes are bit-identical for every count. Workers are joined before return and check cancellation at every output row. `yolox_profile --threads 1,2,4,8` sweeps thread counts. It measured no wall-time speedup on the shared, oversubscribed hosts available (docs/PERF_LEDGER.md PERF-002), so the default stays 1 thread.
- Added geometric ground-zone coverage (`fss-2h5zq.53`): `fss-event corroborate` samples each ground zone on the ground plane (`--visibility-grid N`, default 8x8), projects every sample into the camera (owner homography, or an owner calibrated pose `--pose NAME:W,H,fx,fy,cx,cy,r11..r33,tx,ty,tz` that must agree with it) and, with an owner scene mesh (`--scene-mesh FILE --scene-mesh-digest … --scene-source-digest …`, an fss-twin package) and a pose, tests each camera ray against opaque mesh triangles. The coverage record carries the visible fraction, sampling policy and occlusion model; a zone below the registered threshold (`--visibility-threshold-ppm`, default every sample) is `occluded` or `outside_frustum` with no witness. Without a mesh occlusion is `occlusion_unknown` and every witness predicate, and orient's declared domain and zone cell, say the claim is frustum-only. Grid, threshold, pose and mesh digest are bound into the pipeline generation; new refusals `ERR-CORROBORATE-POSE-INVALID-001` and `ERR-CORROBORATE-VISIBILITY-001`. Such records are version 2 of `fss.recorded_watch_coverage.v1`; image-zone `watch` records keep their exact bytes (pinned against a4d0255). Corroborate coverage therefore has a new pipeline generation: records retained before this change are reported by orient as another generation and never reused. Synthetic scenes and a synthetic mesh only; no calibration or detection-quality claim.
- Added opt-in decode refusals as coverage gaps (`fss-fnrgr` follow-up): `fss-event watch --tolerate-decode-refusals` turns a typed mid-recording decode refusal or source gap into `decode_refused` uncovered intervals naming the error id (MJPEG resumes at the next frame; H.264/H.265 at the next IDR/IRAP), restarts tracking after each gap so no track is bridged, and keeps confirmation latency before every restart uncovered, so no witness (and no follow silence) claims a gap. Without the flag the refusal is unchanged; a tolerant run without refusals is byte-identical.
- Added owner-declared per-sensor privacy masks (`fss-bgqkd`, GOAL-009): `fss-event privacy-mask declare --sensor ID --resolution WxH --rect X,Y,W,H [...]` previews a canonical policy (`fss.privacy_mask_policy.v1`) and retains it only with its exact approval over the sensor's current policy as a new `privacy_mask_policy` authority generation (`KNOWN_LEDGER_DELTA_FAMILIES` is now 12); `privacy-mask show` prints the current binding. Every retained decode path (JPEG/MJPEG luma and RGB, H.264, H.265, video RGB) fills masked pixels (luma 16, chroma 128, RGB 16,16,16) before any consumer; the JPEG luma receipt (now `FSSYREC2`, `fss.recorded_luma_receipt.v2`) and the H.264/H.265 frame receipts (`.v2`) bind the policy digest or an explicit no-policy marker, and the decode key, watch plan identity and coverage pipeline generations bind the mask so lineages never mix. Zones with any masked pixel are uncovered (`privacy_masked`) and orient reports them `not_observable`. Raw `fss-file extract` of a masked sensor and reads of decodes retained under no or a superseded policy are refused (`ERR-PRIVACY-UNMASKED-ACCESS-REFUSED-001`); there is no override. New refusals: `ERR-PRIVACY-MASK-POLICY-001`, `ERR-PRIVACY-MASK-APPROVAL-STALE-001`, `ERR-PRIVACY-MASK-RESOLUTION-001`. Not covered: live capture paths, deletion closure, retention and biometrics. With geometric ground-zone coverage, a corroborate ground zone is also masked when any in-view visibility sample lands on a masked pixel (each sample counted once, `privacy_masked` before `occluded`; such records are `FSSCOV01` version 3); `--tolerate-decode-refusals` masks every frame it decodes and a refused segment stays `decode_refused` (precedence: `decode_refused`, a named `zone_entry`, `privacy_masked`, then the geometric and older reasons).
- Added the detection cascade and trained-detector event path (`fss-704tz`): `fss-event watch` and `fss-event corroborate` accept `--detector-package FILE --detector-digest sha256:… --detector-max-inferences N` (optional `--detector-frames-per-track`, `--detector-min-iou-ppm`, `--detector-minimum-score-ppm`); the verified package runs only on the frames the foreground/Kalman/zone gate selected (zone entry, confirmation, following matches), within an explicit budget whose exhaustion is typed per frame (`ERR-DETECTOR-CASCADE-BUDGET-001`); detections are associated with tracks by integer IoU and retained as uncalibrated class evidence (`fss.detector_class_evidence.v1`) in the sensor's own failure domain. Candidates stay `Unclassified` and single-sensor; corroborated events keep the policy's own evidence; the cascade identity is bound into candidate identities, analyses and coverage pipeline generations. Without a detector the reports are byte-identical (pinned against the pre-cascade tree). `fss-infer package-detect --retain yes` retains a package detection (`fss.package_detection_record.v1`), and `fss-event report --package-report sha256:… --label NAME` tracks it into a `fss.package_analysis_report.v1` that `prepare`/`publish` turn into unclassified, indeterminate package-track events. Retained H.264/H.265 frames now expose Cb/Cr (per-plane receipt digests; the encoded luma receipts are unchanged) and convert to RGB through a declared BT.601 limited-range Q16 transform, so package-detect and the cascade see real colour (`ycbcr420_bt601_limited_rgb`). Wiring only: synthetic scenes, one inference per test, no quality or calibration claim.
- Added `optimized_executor` (fss-bd99t): a prepared CPU executor for F32 Model IR graphs alongside the unchanged scalar reference. Conv2d runs as packed-weight 4x8 register tiles (1x1 convolutions flattened to one GEMM row, depthwise as row accumulation) with fused bias+SiLU; every kernel keeps the reference's per-element operation order, so outputs are bit-identical (0 ULP), certified by seeded differential tests and by the YOLOX conformance test (identical output bits and post-NMS detections; oracle tolerance unchanged). YOLOX-Nano graph execution: median 193 ms vs 3085 ms scalar on one shared AMD EPYC worker (16.0x; `docs/PERF_LEDGER.md` PERF-001). `RgbDetectorPackage::load` and `fss-infer package-detect` default to it; `load_with_backend` and `--kernels scalar-reference` force the reference. The kernel generation is bound into the model digest (`fss.rgb_inference_model_execution.v1`) and `RgbInference::backend()`/`kernel_generation()`/`backend_descriptor()`, so evidence from the two executors never mixes. `examples/yolox_profile.rs` reproduces the per-op profile and timings.
- Admitted YOLOX-Nano (COCO-80, 416x416, Apache-2.0) as FSS's first trained detector package (`fss-q4ngj`, owner decision `fss-x4a.8.1`): a first-party offline importer (`--example yolox_import`, bounded hand-written ONNX protobuf reader) lowers the pinned upstream ONNX (`sha256:c789161e…0b7d`) onto the unchanged Model IR v1 (nearest Resize and exp as exact compositions; no new operator) into an immutable `FMPK` package (`models/yolox-nano/yolox_nano.fmpk`, `sha256:5b656875…8c74`) with Safetensors weights, package spec, LICENSE and NOTICE; reruns are byte-identical. `ingest::rgb_package` loads it only through whole-archive digest, archive, license-policy, graph and weight verification; `fss-infer package-detect` runs it over retained MJPEG (color), H.264 and H.265 (grayscale) imports into a `fss.package_detection_report.v1` report. Conformance against onnxruntime 1.30.0 (lab oracle, not in the repo) on three pinned inputs: max normalized error 3.0e-5 (tolerance 1e-3) and identical detections. Release scalar inference takes ~3 s per frame. No detection-quality, recall or calibration claim on deployment data; `fss-event report` does not yet consume these detections.
- Wired H.265 into ingest and analysis: `fss-file import` retains HEVC Annex-B as media format `hevc` (`--media-format hevc`; auto-detected only when the first NAL header cannot be H.264, otherwise `ERR-INGEST-FORMAT-AMBIGUOUS-001`) with H.265 7.4.2.4.4 access-unit splitting and exact source spans; `RecordedH265Range` decodes IRAP-led ranges in display order (a CRA/BLA-led range skips and lists its RASL pictures), bit-exact against FFmpeg; `fss-file decode`, `fss-event watch` and `fss-event corroborate` accept `hevc` imports. ### Fixed

- Pinned the authority ledger and effect journal against byte-copied forks and sealed the publication lineage against raw writers (`fss-1s6ac`). Durable store handles carry a store pin (`fss.durable_store_pin.v1`: role plus the opened file's device, inode and birth time); compile paths record the pins of the stores they compiled against (outside the seal and publication digest, so replica digests and handoff bytes are unchanged). Recording refuses a publication compiled against another store (`lineage_foreign_authority`) or an unpinned/moved store (`lineage_authority_unpinned`); lineage-bound classification refuses a store that holds a publication's history but is not the store it recorded (`meaningful_delta_authority_fork`, `meaningful_delta_journal_fork`) or is unpinned (`meaningful_delta_authority_unpinned`, `meaningful_delta_journal_unpinned`). The lineage families and objects are a sealed namespace: `DurableReferenceLedger::append` refuses them (`ERR-LEDGER-SEALED-NAMESPACE-001`), `record_reference_publication` writes them through a gated writer with a lineage write seal (`fss.reference_lineage_write_seal.v1`), and readers refuse, typed, any lineage write outside a sealed batch (`lineage_unsealed_write`). This closes the fss-mnlz1 residuals R5-B (displaced basis), R5-C (junk first entry) and R7-A (same-batch proof marker). A raw lineage write that extended the latest publication used to be credited as a step; it is now refused at append, and refused by readers if planted in the journal bytes. Filesystem-level residuals are stated in SECURITY.md 14.1. Digest domains 118 -> 120.
- Restored the fss-core half of the v3 cancellation-proof records (`fss-thzlz`), which a 2026-09-22 bulk merge had dropped while keeping its callers. That had left `fss-reference` uncompilable (`fss-pod9x`).
- Removed duplicate registry rows and a stale duplicate of topology layers L3/L4 introduced by the same bulk merge, and restored the byte-exact staleness check in `scripts/robot_docs_checker.py`, which the merge had weakened.

### Changed

- Agent-facing projection now preserves resource pressure as its own semantic dimension instead of laundering it into material world change.
- Meaningful-delta comparison now separates semantic world content from routine successor-anchor movement, permitting certified silence across harmless authority commits.
- Contradiction resolution and removal of a previously known premise are retained as critical decision-impact changes.
- Compression receipts permit explicitly receipted partial semantic classes while continuing to forbid omission of critical items, contradictions, or invalidations.
- Public situation compilation routes through the effect-state guard by default.
- Expansion and continuation semantics are progressively moving from conversational strings toward content-bound, capability-scoped contracts.
- Hosted GitHub execution remains supplementary. Repository-owned local qualification and retained DSR receipts remain the release authority.

## 0.1.0 - Foundation snapshot

### Added

- Pure-Rust workspace and crate topology for the semantic reference kernel, object store, durable evidence ledger, publication spine, reference acquisition/replay path, and CLI laboratory.
- Canonical identities, hashing, timestamps, evidence anchors, sensor capsules, coverage witnesses, event hypotheses, effect journals, obligations, receipts, and root-last object publication.
- Deterministic virtual camera source generation, delivery mutation, mock-model execution, unknown-presence policy evaluation, alert preparation/dispatch/reconciliation, and replay bundles.
- Repository constitutions, ADRs, machine registries, JSON Schemas, local qualification scripts, dependency audits, release tooling, and layered integrity manifests.
- Agent cognition and control architecture covering missions, sessions, epistemic states, situation frames, possible worlds, affordances, plans, effects, learning, workspaces, and handoffs.

### Security and correctness

- Workspace crates forbid memory-unsafe Rust.
- Negative claims require explicit coverage evidence.
- Model output alone cannot grant effect authority.
- External effects use prepare/commit/watch/reconcile semantics and retain indeterminate outcomes.
- Canonical publication is child-first and root-last.
- Stable identifiers are never silently renumbered or rebound.
